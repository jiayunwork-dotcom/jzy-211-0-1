一个在功率器件厂做工艺整合的朋友找我帮忙。他们的探针台对晶圆上每颗二极管测一条正向 I–V 扫描，一片晶圆几千颗，一个批次二十几片。现在工程师把数据导进表格，用手工挑的两个点估理想因子，串联电阻基本不算，想看参数在晶圆上的分布还得自己画图。他想要一个带网页的小系统：数据传上去，后台逐颗提取二极管参数，网页上以晶圆图的形式看分布、点开单颗看拟合。

每颗管芯的一条扫描是若干 (电压, 电流) 点，附带管芯坐标、测试温度和测试时间。要提取的是饱和电流、理想因子和串联电阻，模型是带串联电阻的单指数二极管方程，热电压由测试温度决定。核对参考：300 K 时热电压约 25.852 mV；饱和电流 1e-14 A、理想因子 1、无串联电阻，0.6 V 处电流约 1.201e-4 A；理想因子改为 2，同一电压下电流约 1.096e-9 A。低电流段会受漏电和仪器底噪影响，高电流段串联电阻占主导，提取方法怎么定（整条曲线直接做非线性拟合、先按区段粗估再精修、或变换成显式形式后求解），坏点和底噪怎么剔除，由你决定，在文档里说明它在什么情况下会给出错误的串联电阻。每颗的结果要附拟合残差，残差超过阈值的标记为提取失败而不是给个数字了事。用已知参数合成的曲线（叠加一定噪声）送进去，三个参数都要在给定容差内还原。

数据是分块上传的：探针台每测完一段就传一批，同一片晶圆可能分成很多块，顺序也不一定。复测很常见，同一颗管芯出现第二条扫描时以测试时间较晚的为准。处理按晶圆以后台作业运行，页面上能看到进度并可以取消，取消后不留下这片晶圆的半截结果。关键要求：不管数据分成多少块、以什么顺序到达、中间夹杂多少次复测，最终每颗管芯的参数和整片晶圆的汇总（各参数的中位数、分位数、良率）必须与把最终有效数据一次性交给服务处理的结果完全相同。是每来一块就增量更新，还是攒够了再整片重算，由你权衡并说明代价。

判级规则（每个参数的上下限、失败算不算不良）存成版本，结果绑定所依据的规则版本。发布新规则版本后，已有结果按新规则重新判级（不必重新拟合），网页上能对比新旧两个版本下哪些管芯的等级变了。

网页部分：批次和晶圆列表；晶圆图按所选参数着色，失败管芯另有标识；点开管芯显示测量点、拟合曲线和残差；作业进度与取消；规则版本对比。界面不需要复杂交互，清楚即可。

拒收并指明原因：扫描点少于 5 个、电压不单调、出现负电流或非数值、测试温度不在 200 K 到 500 K 之间、管芯坐标超出该晶圆的定义范围、规则里上限小于下限。

测试要包括：三个参考值；合成曲线参数还原；无串联电阻时退化情形；提取失败的判定；分块乱序与复测后与一次性处理一致；取消不留半截结果；规则版本切换只改判级不改参数。

后端 Python 3.12 + FastAPI，结果存 PostgreSQL 16，数值部分可用 NumPy 与 SciPy；前端 React 18，用 Vite 构建。二极管模型、参数提取、数据接入与复测合并、作业调度、判级与规则版本、存储、接口路由在后端各自成模块，前端组件也按页面拆开。后端镜像基于 python:3.12-slim，前端用 node:20-alpine 构建后交给 nginx:1.27-alpine 提供，连同 postgres:16-alpine 一起编进 docker compose。后端测试用 pytest。
